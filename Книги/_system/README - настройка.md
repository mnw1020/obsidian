# Настройка книжной базы

## QuickAdd

Создай 11 Choice типа `Macro` и добавь в каждый соответствующий `User Script`:

1. `Книги - Добавить книгу` -> `Книги/_system/QuickAdd/add_book.js`
2. `Книги - Добавить чтение` -> `Книги/_system/QuickAdd/add_reading.js`
3. `Книги - Редактировать чтение` -> `Книги/_system/QuickAdd/edit_reading.js`
4. `Книги - Открыть автора` -> `Книги/_system/QuickAdd/open_author.js`
5. `Книги - Открыть серию` -> `Книги/_system/QuickAdd/open_series.js`
6. `Книги - Проверить библиотеку` -> `Книги/_system/QuickAdd/audit_library.js`
7. `Книги - Исправить безопасное` -> `Книги/_system/QuickAdd/safe_fix_library.js`
8. `Книги - Авторы` -> `Книги/_system/QuickAdd/authors_overview.js`
9. `Книги - Серии` -> `Книги/_system/QuickAdd/series_overview.js`
10. `Книги - Связать с кино` -> `Книги/_system/QuickAdd/link_adaptation.js`
11. `Книги - Экранизации` -> `Книги/_system/QuickAdd/adaptations_overview.js`

У `Добавить книгу`, `Добавить чтение`, `Редактировать чтение`, `Проверить библиотеку`, `Исправить безопасное`, `Авторы`, `Серии`, `Связать с кино` и `Экранизации` включи молнию, чтобы команды были доступны как `QuickAdd: ...` для кнопок.
Для `Открыть автора` и `Открыть серию` молнию тоже можно включить. Основной вызов этих двух команд идет по ссылкам из Bases.

## История чтений

Отдельной папки `Книги/Чтения` больше нет.

В YAML книги хранятся только актуальные агрегаты:

```yaml
date: "2026-09-16"
rating: 8
read_count: 2
```

Для Non-fiction свойство `rating` не используется.

Подробная история находится в конце самой книги, внутри секции `## История чтений`.
QuickAdd управляет только текстом между служебными маркерами:

```text
<!-- BOOK-READINGS:START -->
...
<!-- BOOK-READINGS:END -->
```

Остальной текст книги, конспект, картинки и заметки скрипты не изменяют.

`Добавить чтение`:

- берет открытую книгу либо предлагает выбрать книгу;
- определяет следующий номер чтения;
- спрашивает дату, а для художественной книги еще оценку;
- спрашивает комментарий;
- добавляет новую запись непосредственно в карточку книги **после предыдущих чтений**;
- история всегда идет по возрастанию: `Чтение 1`, ниже `Чтение 2`, затем `Чтение 3` и т.д.;
- пересчитывает `date`, `rating` и `read_count`.

`Редактировать чтение`:

- берет открытую книгу либо предлагает выбрать книгу;
- показывает все ее чтения;
- позволяет изменить дату, оценку и комментарий;
- заново пересчитывает агрегаты книги.

Старые неполные даты `YYYY-MM` и `YYYY` поддерживаются и при редактировании сохраняются.

## Авторы и серии

Отдельных страниц для каждого автора и каждой серии нет.

В YAML книги хранятся обычные данные:

```yaml
authors:
  - "Олдос Хаксли"
series: "Название серии"
series_index: 2
```

В таблицах `Книги.base` колонки `Автор` и `Серия` являются вычисляемыми ссылками.
При клике они вызывают QuickAdd через `obsidian://quickadd` и передают выбранное имя.

QuickAdd переиспользует две служебные страницы:

- `Книги/_system/Автор.md`
- `Книги/_system/Серия.md`

`Автор.md` показывает все книги выбранного автора и группирует их по сериям.
`Серия.md` показывает книги выбранной серии по порядку и с кликабельными авторами.

Новые авторы и серии не требуют создания дополнительных Markdown-файлов.

## Перечитывания в общей базе

В `Книги.base` есть view `Перечитанные` с фильтром `read_count > 1`.
Одна строка там всегда соответствует одной книге. Подробная история открывается внутри самой книги.

## Структура данных

Свойства `kind` и `status` не используются.

Книга определяется по расположению в `Книги/Художественные` или `Книги/Non-fiction` и наличию `title` + `authors`.
История чтений является частью Markdown самой книги и отдельной сущностью в файловой системе не является.

## Как теперь устроены серии

Пустые свойства `series:` и `series_index:` у одиночных книг удалены. Они появляются только у книг, которые реально отнесены к серии.

В `Книги.base` добавлен view `Серии`: все книги с серией сгруппированы по названию серии и отсортированы по `series_index`.

При добавлении новой книги QuickAdd больше не просит вводить название существующей серии вручную:

- после ввода автора показывает уже известные серии этого автора;
- можно выбрать `Без серии`;
- можно выбрать существующую серию;
- можно создать `➕ Новая серия`;
- для выбранной серии предлагается следующий номер, который можно изменить вручную.

Если команда запускается со служебной страницы серии, серия уже выбрана, а следующий номер предлагается автоматически.

На служебной странице `Серия.md` есть QuickAdd-кнопка `➕ Добавить книгу в серию`.


## Проверка библиотеки

QuickAdd-команда `Книги - Проверить библиотеку` проходит всю книжную базу и создает/перезаписывает один отчет:

`Книги/_system/Проверка библиотеки.md`

Перед основной проверкой скрипт ищет варианты написания авторов **и названий серий** и предлагает нормализацию. Объединение выполняется **только после твоего выбора**: можно выбрать каноническое имя/название или пропустить группу. После этого отчет строится уже по актуальным данным.

Нормализатор умеет находить:

- различия в пунктуации и регистре: `Лю Цысинь` / `Лю Цысинь.`;
- перестановку слов: `Лю Цысинь` / `Цысинь Лю`;
- очень близкие написания с небольшой опечаткой.

Для серий работает тот же принцип: пунктуация/регистр и небольшие опечатки предлагаются как кандидаты на объединение. `series_index` при объединении не меняется.

После нормализации скрипт проверяет:

- обязательные `title` и `authors`;
- остаточные wikilinks в авторах и сериях;
- корректность дат, `read_count` и рейтингов;
- отсутствие `rating` у Non-fiction;
- целостность встроенной истории чтений;
- совпадение `date`, `rating`, `read_count` с историей;
- возможные дубли книг;
- варианты и похожие написания авторов и серий;
- `series` / `series_index`;
- повторяющиеся номера и пробелы в сериях.
- ссылки на отсутствующие локальные вложения в книжных Markdown-файлах;
- картинки внутри `Книги/`, на которые не ссылается ни один Markdown-файл vault;
- двусторонность связей `adaptations` ↔ `Первоисточники`;
- битые и повторяющиеся ссылки книга ↔ кино;
- чтобы `adaptations` вел только на реальные карточки `movies`/`serial`, а `Первоисточники` — только на реальные карточки книг.

После проверки отчет открывается автоматически. На главной `_index.md` кнопки проверки больше нет: сервисный аудит запускается со страницы `Книги/_system/Проверка библиотеки.md`. Там же находится кнопка `🛠 Исправить безопасное`.


## Обзор авторов

QuickAdd-команда `Книги - Авторы` каждый раз заново собирает одну служебную страницу:

`Книги/_system/Авторы.md`

Отдельные файлы авторов по-прежнему не создаются. В обзоре одна строка соответствует одному автору и показывает:

- количество книг автора в библиотеке;
- среднюю оценку только по книгам, где `rating` указан;
- последнюю прочитанную книгу и дату чтения.

Имя автора является ссылкой на существующую динамическую страницу `Автор.md`.
На главной `_index.md` есть кнопка `👥 Авторы`. Она запускает QuickAdd, обновляет обзор из текущих данных и открывает его. На самой странице обзора есть кнопка `🔄 Обновить обзор авторов`.


## Обзор серий

QuickAdd-команда `Книги - Серии` каждый раз заново собирает одну служебную страницу:

`Книги/_system/Серии.md`

Отдельные файлы для каждой серии не создаются. В обзоре одна строка соответствует одной серии и показывает:

- автора или авторов серии;
- количество книг серии в библиотеке;
- сколько книг серии прочитано (`read_count > 0`);
- среднюю оценку только по книгам, где `rating` указан;
- последнюю прочитанную книгу и дату.

Название серии является ссылкой на существующую динамическую страницу `Серия.md`. На главной `_index.md` есть кнопка `📚 Серии`, а на странице конкретной серии — кнопка `📚 Все серии`.

## Состояние библиотеки и журнал изменений

В начале `Книги/_system/Проверка библиотеки.md` после каждого полного аудита выводится краткое состояние:

- книг;
- уникальных авторов;
- серий;
- изображений;
- fiction / non-fiction;
- перечитанных книг (`read_count > 1`);
- оцененных художественных книг.

Если во время полного аудита ты подтверждаешь объединение вариантов автора или серии, изменение дополнительно записывается в постоянный файл:

`Книги/_system/Журнал изменений.md`

Он не перезаписывается при следующем аудите и хранит дату, исходное написание, каноническое написание и число измененных книг.

## Проверка автора и серии при добавлении книги

`Книги - Добавить книгу` до создания файла сравнивает введенные имена авторов и новую серию с уже существующими значениями. Если найдено очень похожее написание, QuickAdd предлагает использовать существующее либо явно оставить новое. Никаких автоматических объединений без выбора пользователя нет.

## Связь книги с кино

На каждой карточке книги есть кнопка `🎬 Связать с кино`. Она запускает `Книги - Связать с кино`.

Скрипт:

- использует открытую книгу либо предлагает выбрать книгу;
- ищет в этом же vault карточки внутри `Кино/` с тегом `movies` или `serial`;
- исключает `Кино/Просмотры`, `Кино/Сезоны` и `Кино/_system`;
- предлагает выбрать фильм или сериал;
- добавляет в книгу `adaptations` со ссылкой на карточку кино;
- добавляет в карточку кино `Первоисточники` со ссылкой на книгу;
- не создает повторную связь, если пара уже связана с обеих сторон.

Полный `Книги - Проверить библиотеку` дополнительно проверяет эту связь **с обеих сторон**. Он сообщает об ошибке, если:

- книга содержит фильм в `adaptations`, но фильм не содержит книгу в `Первоисточники`;
- фильм/сериал содержит книгу в `Первоисточники`, но книга не содержит его в `adaptations`;
- ссылка ведет на отсутствующий файл;
- одна связь записана в одном свойстве несколько раз;
- `adaptations` ведет не на карточку с тегом `movies`/`serial`;
- `Первоисточники` ведет не на карточку книги.

Все такие проблемы выводятся в отдельном разделе `🎬 Связи с кино`. Аудит их **не исправляет автоматически**.

Существующие ручные ссылки на фильмы внутри текста книги не мигрируются автоматически: такая ссылка может быть просто тематической, а не означать экранизацию.

## Легкая автопроверка после изменений

После `Добавить книгу`, `Добавить чтение` и `Редактировать чтение` автоматически проверяется только измененная книга и ее серия. Проверяются обязательные свойства, связка `series`/`series_index`, даты, `read_count`, рейтинг, история чтений и дубли номера внутри серии.

Если проблем нет, дополнительных окон нет. Если найдена проблема, QuickAdd показывает предупреждение и предлагает запустить полную `Проверить библиотеку` для подробностей. Полный аудит по-прежнему запускается отдельно и не тормозит каждое изменение.


## Безопасное автоисправление

`Книги - Исправить безопасное` вызывается кнопкой со страницы `Проверка библиотеки.md`. Команда не исправляет спорные данные. Она умеет только:

- удалять точные дубли ссылок в известных взаимных свойствах;
- нормализовать пробелы авторов и использовать вариант без конечной точки только когда такой канонический вариант уже существует;
- пересчитывать `read_count` из неповрежденной встроенной истории чтений;
- достраивать отсутствующую обратную ссылку по явным правилам `adaptations` ↔ `Первоисточники`, `related` ↔ `related`, `continued_by` ↔ `continues`;
- optional `adapted_from` → `adaptations` — проверяется только когда `adapted_from` реально присутствует, и не требуется от всех карточек кино.

После исправлений нужно снова запустить полный аудит.

## Общие взаимные связи

Проверка взаимности работает не по догадке, а по списку `RELATION_RULES` внутри `audit_library.js`. Сейчас определены:

- `adaptations` ↔ `Первоисточники`;
- `related` ↔ `related`;
- `continued_by` ↔ `continues`;
- optional `adapted_from` → `adaptations` — проверяется только когда `adapted_from` реально присутствует, и не требуется от всех карточек кино.

Если позже появится новая семантическая пара полей, ее следует явно добавить в `RELATION_RULES`, чтобы обычная односторонняя ссылка случайно не считалась ошибкой.

## Обзор экранизаций

`Книги - Экранизации` динамически пересобирает `Книги/_system/Экранизации.md`. Таблица содержит: `Книга | Автор | Экранизация | Тип | Моя оценка книги | Моя оценка кино`. На главной есть кнопка `🎬 Экранизации`.

Полный аудит дополнительно показывает книги без `adaptations`, для которых найден фильм/сериал с очень похожим названием. Это только подсказка; связь автоматически не создается.

## Журнал обслуживания и состояние

`Книги/_system/Журнал изменений.md` теперь хранит не только нормализации, но и безопасные исправления, добавление новых книг и создание связей с кино. Машиночитаемые HTML-маркеры событий позволяют аудиту показывать в блоке состояния `Последняя нормализация` и `Последнее изменение структуры`.
