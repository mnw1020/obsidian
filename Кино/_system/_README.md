# Кинотека - актуальная инструкция

> Версия сборки: 24.09.2026. Основной каталог: `Кино/`.
>
> Важно: в служебных скриптах встроен личный ключ Kinopoisk Unofficial API. Не публикуй `_system/` в открытом репозитории.

## Что нужно в Obsidian

Минимум для основной логики:

- **QuickAdd** - запуск User Script-команд.
- **Dataview** - динамические блоки, кнопка `🔎 Найти похожие`, страницы актёров/жанров/режиссёров и аналитика.
- **Buttons** - кнопки на `Кино/_index.md`.
- **Bases** - файл `Кино/_Кино.base` и табличные представления кинотеки.

Если используется дополнительный grid-вид `dynamic-views-grid` в `_Кино.base`, соответствующий плагин тоже должен оставаться включённым.

## Добавление фильма или сериала

`Examples_Attachments_movies.js` - главный скрипт создания карточки.

Источники используются так:

1. **Kinopoisk Unofficial API** - данные по известному КП ID, поиск по названию и состав по `filmId`.
2. **OMDb / IMDb** - оригинальные данные и IMDb-связь, когда она доступна.
3. **Wikidata**, прямой сайт Кинопоиска и **Movie Planner** - резерв, если основной источник не дал нужное поле.

После создания скрипт:

- записывает YAML карточки;
- создаёт `Кино/_system/Роли/<карточка>.роли.md`;
- вставляет раскрывающийся блок `🎭 Роли`;
- вставляет кнопку `🔎 Найти похожие` с пустой строкой до и после;
- запускает персональный прогноз оценки.

OMDb API Key по-прежнему задаётся в настройках User Script `Examples_Attachments_movies.js`. Ключ КП уже встроен по запросу владельца базы.

## Роли

В основной карточке роли не занимают экран постоянно. Используется блок:

`🎭 Роли` -> клик -> раскрывается содержимое `Кино/_system/Роли/<название>.роли.md`.

Файл ролей хранит актёров, роли, режиссёров и обратную ссылку на основную карточку. `Кино - Обновить роли актёров` сначала использует КП API, затем резервные источники.

Скрипты добавления/редактирования просмотров и сезонов, а также `Пересобрать карточку`, сохраняют блок ролей и кнопку рекомендаций при перестройке тела карточки.

## Рекомендации

На каждой карточке есть кнопка **`🔎 Найти похожие`**. Она записывает текущую карточку в `_system/Прогноз/рекомендации_state.json` и открывает `_system/рекомендации.md`.

Рекомендации объединяют:

- похожие фильмы по **Кинопоиск API**;
- MovieLens вкусовых соседей;
- локальные признаки твоей кинотеки;
- персональный прогноз оценки.

Для оценки 1-4 сильнее ищутся более перспективные альтернативы близкой темы. Для 6-10 сильнее учитывается сходство с референсом. Уже оценённые фильмы исключаются.

На странице есть диагностика источников КП. Movie Planner и прямой HTML Кинопоиска остаются только резервом.

## Прогноз оценки

`predict_rating.js` рассчитывает прогноз для активной карточки. `predict_all_ratings.js` пересчитывает всю кинотеку.

Используются два слоя:

- локальная интерполяция твоих уже выставленных оценок;
- MovieLens collaborative layer из `_system/Прогноз/movielens_neighbors.json`.

Реальное поле `Оценка` прогнозатор не перезаписывает.

### MovieLens

`Обновить модель MovieLens.bat` полностью перестраивает collaborative-модель. Полная перестройка одновременно обновляет компактный каталог названий/годов/жанров.

`Обновить каталог рекомендаций.bat` нужен только для быстрого повторного добавления метаданных каталога в уже существующую модель без повторного прохода по `ratings.csv`. В обычной работе запускать его не нужно.

`ml-32m.zip` может оставаться локальным и быть исключён из Git.

## Просмотры и сезоны

- `add_viewing.js` создаёт запись в `Кино/Просмотры/` и перестраивает историю в карточке.
- `edit_viewing.js` изменяет существующую запись просмотра.
- `add_season.js` создаёт сезон в `Кино/Сезоны/` и обновляет сериал.
- `edit_season.js` изменяет сезон.
- `rebuild_card.js` пересобирает отображаемые блоки по служебным файлам.

Во всех этих операциях постоянные блоки `🎭 Роли` и `🔎 Найти похожие` должны сохраняться.

## Франшизы

`Франшиза` -> `edit_franchise.js`. Карточки франшиз находятся в `Кино/Франшизы/`. Скрипт меняет только связь `Франшиза` и номер `Часть`, а таблица произведений строится динамически.

## Проверка и исправление

Рекомендуемый порядок после крупных изменений:

1. Запустить `Кино - Проверить кинотеку`.
2. Посмотреть `Кино/_system/Проверка кинотеки.md`.
3. При однозначных форматных ошибках запустить `Кино - Исправить безопасное`.
4. Повторить проверку.

Аудит проверяет YAML, ID, связи, роли, имена людей, дубли, просмотры, сезоны, франшизы, наличие раскрывающегося блока ролей и единственной кнопки рекомендаций.

## Структура

- `Кино/*.md` - основные фильмы и сериалы.
- `Кино/Просмотры/` - отдельные просмотры.
- `Кино/Сезоны/` - сезоны сериалов.
- `Кино/Франшизы/` - франшизы.
- `Кино/_system/Роли/` - companion-файлы актёров/ролей.
- `Кино/_system/Прогноз/` - MovieLens, state и кэши рекомендаций.
- `Кино/_system/` - скрипты и служебные страницы.
- `Кино/_Кино.base` - основная база представлений.
- `Кино/_Аналитика прогнозов.md` - аналитика качества прогнозов.

## Что не надо делать вручную

- Не копировать роли обратно в тело карточки - они живут в `_system/Роли/`.
- Не редактировать `рекомендации_state.json` вручную.
- Не запускать BAT каталога после каждого добавленного фильма.
- Не удалять маркеры `KINO:ROLES:EMBED:V2` и `KINO:RECOMMEND:BUTTON:V2`: по ним скрипты сохраняют постоянные блоки при перестройке карточки.
