## Оформление

Кинотека использует общий тёмный интерфейс для компьютера и телефона. После постера в самом низу карточки находится компактный раскрывающийся блок «Все свойства».

- Шапка и подробности читают свойства карточки через `Кино/_system/kino_ui.js`. Полные свойства и роли раскрываются по нажатию; исходный Markdown доступен в редакторе.
- Роли хранятся в `Кино/_system/Роли/`. В блоке с режиссёром, жанрами и франшизой надпись «Роли и актеры» сопровождается кнопкой «Показать»: список раскрывается вниз, а кнопка меняется на «Скрыть». Поле `Роли файл` позволяет открыть исходную заметку.
- Общие стили — `_system/kino-design.css`. Карточки, главные и служебные страницы сами запускают общий загрузчик `_system/vault_styles.js`, без CSS-сниппетов и зависимости от запуска локального плагина на Android. Он также подключает стили библиотеки и общие правила Bases, один раз на приложение; изменения CSS подхватываются автоматически. Плагин «Библиотека и кинотека» (`book-preview-defaults`) дополнительно запускает загрузчик при старте Obsidian. Для прямого открытия нативной базы сразу после запуска нужен этот плагин либо предварительное открытие любой страницы коллекций; после этого стили сохраняются до закрытия приложения.
- Страницы кинотеки используют доступную ширину панели. Страницы актёра, режиссёра и жанра занимают 80% ширины и выровнены по центру.
- В шапке карточки релиз, просмотр, продолжительность и кнопки «Связать с книгой», «🔎 Найти похожие» расположены в одном ряду. Дата релиза выводится как `dd.mm.yyyy`, продолжительность — `hh:mm`; на узкой панели ряд прокручивается по горизонтали. Если в базе известен только год релиза, он сохраняется без выдуманной даты.
- `card_layout.js` сохраняет личный Markdown при добавлении, редактировании и пересборке карточек. Маркеры `KINO:UI:START/END`, `KINO:PROPERTIES:START/END`, `SEASONS:START/END` и `KINO:VIEWINGS:START/END` нужны для обновления соответствующих блоков. Устаревший отдельный блок `KINO:RECOMMEND:BUTTON:V1/V2` удаляется: кнопку рекомендаций теперь рисует общий интерфейс.
- Новые карточки получают оформление автоматически через существующий QuickAdd-шаблон. Команда **Пересобрать карточку** обновляет отображаемые блоки существующей карточки.

# Кинотека - актуальная инструкция

> Актуальная инструкция: 15.10.2026. Основной каталог: `Кино/`.
>
> Важно: в служебных скриптах встроен личный ключ Kinopoisk Unofficial API. Не публикуй `_system/` в открытом репозитории.

## Что нужно в Obsidian

Минимум для основной логики:

- **QuickAdd** - запуск User Script-команд.
- **Dataview** - динамические блоки, кнопка `🔎 Найти похожие`, страницы актёров/жанров/режиссёров и аналитика.
- **Buttons** - кнопки на `Кино/_index.md`.
- **Bases** - файл `Кино/_system/_Кино.base` и табличные представления кинотеки.

Если используется дополнительный grid-вид `dynamic-views-grid` в `_Кино.base`, соответствующий плагин тоже должен оставаться включённым.

Из карточки фильма или сериала пересчитывает «По данным», «По сюжету» и итог этой карточки; из страницы «Проверка кинотеки» — всю коллекцию с новым подбором параметров. На странице проверки есть одноимённая кнопка с прогрессом и остановкой. Расчёт выполняется внутри Obsidian, личные оценки сохраняются. Незавершённые задачи остаются в очереди. Подробности — [[Кино/_system/Прогноз/README|три прогноза и сохранённый разбор]].

**Журнал изменений:** оформлен как остальные служебные страницы; новые события показаны сверху и раскрываются по нажатию. Кнопка **Почистить** сохраняет точную копию заметки в `Кино/_system/redesign-backups/journal-*.md`, затем удаляет записи. После очистки доступна ссылка **Открыть копию**; в пустом журнале кнопка отключена. Новые события добавляются автоматически. Интерфейс и встроенные стили: `journal_ui.js` и `kino-journal.css`; установка нового snippet или QuickAdd-команды не требуется.

- `Франшизу` -> `Франшиза`.

## Добавление фильма или сериала

`Examples_Attachments_movies.js` - главный скрипт создания карточки.

Источники используются так:

1. **Kinopoisk Unofficial API** - данные по известному КП ID, поиск по названию и состав по `filmId`.
2. **OMDb / IMDb** - оригинальные данные и IMDb-связь, когда она доступна.
3. **Wikidata**, прямой сайт Кинопоиска и **Movie Planner** - резерв, если основной источник не дал нужное поле.

После создания скрипт:

- записывает YAML карточки;
- создаёт `Кино/_system/Роли/<карточка>.роли.md`;
- вставляет раскрывающийся блок `🎭 Роли`;
- подключает общий интерфейс с кнопкой `🔎 Найти похожие` рядом с «Связать с книгой»;
- после заполнения ролей и франшизы рассчитывает прогноз по данным, прогноз по сюжету и итог.

OMDb API Key по-прежнему задаётся в настройках User Script `Examples_Attachments_movies.js`. Ключ КП уже встроен по запросу владельца базы.

## Роли

В основной карточке роли не занимают экран постоянно. Используется блок:

`🎭 Роли` -> клик -> раскрывается содержимое `Кино/_system/Роли/<название>.роли.md`.

Файл ролей хранит актёров, роли, режиссёров и обратную ссылку на основную карточку. `Кино - Обновить роли актёров` сначала использует КП API, затем резервные источники.

Скрипты добавления/редактирования просмотров и сезонов, а также `Пересобрать карточку`, сохраняют блок ролей и кнопку рекомендаций при перестройке тела карточки.

## Рекомендации

На главной первая кнопка **«Добавить»** открывает единое окно. Введи ID или ссылку Кинопоиска / IMDb и выбери фильм или сериал.

- **Рекомендации** — открывает подбор для указанного фильма. Карточка в коллекции не обязательна. Источники включаются вручную, затем нажимается «Загрузить рекомендации».
- **Прогноз** — показывает текущий прогноз по данным и сюжету с подробным разбором. Личная оценка не нужна, карточка не создаётся.
- **Добавить** — открывает существующую карточку, если найден любой из двух ID. Для нового произведения требуется личная оценка от 1 до 10; дата просмотра ставится сегодняшняя. В этом же окне показывается ход поиска, сохранения и расчёта прогноза, затем открывается карточка. Сохранение выполняет прежний `Examples_Attachments_movies.js` через существующий `_templates/imdb_template.md`; файл ролей формирует его же `writeRoleFile`. Дата и оценка первого просмотра остаются в свойствах основной карточки. Отдельная запись просмотра создаётся только командой добавления повторного просмотра. После записи карточки открывается прежний выбор франшизы: можно выбрать существующую, создать новую или пропустить. Связь и номер части сохраняются перед расчётом прогноза; переход к карточке происходит после завершения.

IMDb ID сначала сопоставляется с Кинопоиском. Если совпадения нет, используются сведения OMDb и уже настроенный ключ QuickAdd. При ошибке прогноза сохранённая карточка остаётся в базе; расчёт можно повторить из неё.

Открытие самого окна не отправляет запросы. Предпросмотр прогноза существует в окне до закрытия; карточку при необходимости добавляют отдельно.

На каждой карточке в верхнем ряду рядом с **«Связать с книгой»** есть кнопка **`🔎 Найти похожие`**. Она записывает текущую карточку в `_system/Прогноз/рекомендации_state.json` и открывает `_system/Рекомендации.md`.

Рекомендации объединяют:

- похожие фильмы по **Кинопоиск API**;
- локальные признаки твоей кинотеки;
- персональный прогноз оценки.

Для оценки 1-4 сильнее ищутся более перспективные альтернативы близкой темы. Для 6-10 сильнее учитывается сходство с референсом. Уже оценённые фильмы исключаются.

На странице есть диагностика источников КП. Movie Planner и прямой HTML Кинопоиска остаются только резервом.

Для источника **ИИ** выбери подключение и модель в компактной панели. Кнопка **Настройки ИИ** открывает отдельное окно: подключения слева, сервер, протокол, ключ и модели справа. Ключ скрыт по умолчанию. Изменения применяются кнопкой **Сохранить**; при закрытии несохранённого черновика появляется подтверждение.

При обычном открытии рекомендаций Кинопоиск по умолчанию выключен. Загрузка фильмов и расчёт прогноза запускаются кнопкой **Загрузить рекомендации**. При обычном открытии страницы прошлый фильм и результаты не восстанавливаются. Действие **«Рекомендации»** из окна добавления выбирает только текущий фильм; источники остаются выключенными. Переключение источников, модели, подключения, диапазона лет и расшифровка ключей сами по себе запросы не запускают.

Рядом с каждой моделью в настройках есть **Проверить**: короткий запрос проверяет именно её сервер, протокол и ключ, не создавая подборку фильмов. Результат показывается в карточке модели и сохраняется вместе с настройками кнопкой **Сохранить**. Время ожидания проверки — до 60 секунд.

В **Параметрах подключения** каждой модели можно указать отдельный сервер и протокол. Поддерживаются Responses, Chat Completions и Anthropic Messages. Адрес сервера — базовый URL, без конечного `/responses`, `/chat/completions` или `/messages`. Загрузка моделей дополняет список, сохраняя ручные записи. Новые или изменённые маршруты отмечаются как непроверенные.

Настройки версии 3 хранятся в `ai_settings.enc.json` с прежним шифрованием и паролем. После перезапуска расшифруй файл; кнопка **Заблокировать** очищает текущую сессию. Tokenator установлен однократно: удаление или изменение подключения не восстанавливает его автоматически. Проверенные восемь моделей доступны через общий `/v1/responses`, по умолчанию выбрана `free-gpt-6-astra`.

Подборка ИИ содержит до 12 фильмов. Для предпочтений передаются 20 близких оценённых примеров с короткими описаниями; для GPT 5/6 через Responses задан уровень рассуждений low. Время ожидания — до 5 минут, во время загрузки показывается прошедшее время. Если сервер оборвал JSON, сохраняются полностью полученные фильмы и показывается отметка о неполном ответе. Markdown и пояснения вокруг JSON не мешают чтению списка.

## Прогноз оценки

В карточке показаны три значения: **«По данным»**, **«По сюжету»** и крупный **итог**. Нажатие на весь блок открывает окно «Как получен прогноз» с вкладками «Итог», «Данные» и «Сюжет». Оно показывает сохранённый расчёт именно отображаемых значений: исходные данные, формулы, соседей, их оценки, веса и вклады.

Прогноз по данным использует публичные рейтинги, свойства карточек и до **155 ближайших соседей**. Базовая калибровка и поправки по категориям используют всю оценённую обучающую базу. Прогноз по сюжету использует только описания, локальные векторы **EmbeddingGemma 300M q8** и личные оценки сюжетных соседей. Параметры сюжетной ветки подбираются по её собственной ошибке. Веса итоговой смеси обратно пропорциональны средней абсолютной ошибке источников на одинаковых внутренних проверочных карточках, ограничены диапазоном **25–75%** и проверяются вложенной перекрёстной проверкой 5×4. При недостаточной истории используются 50/50. Само произведение и его дубликаты по IMDb/КП ID исключаются из собственного обучения и подбора параметров.

Независимая проверка дала среднюю абсолютную ошибку: данные — **1,4921**, сюжет — **1,7637**, смесь 50/50 — **1,5764**, итог по надёжности — **1,5647** балла. Текущие веса для новых карточек: **54,17% данные / 45,83% сюжет**; у оценённых карточек веса получены без их внешней группы. Итог точнее равного среднего на этой проверке, но уступает данным отдельно; улучшение относительно данных не подтверждено. Расчёт объединяет неокруглённые значения обеих веток.

После изменения личных оценок, признаков или описаний оценённой базы веса автоматически проверяются заново при следующем расчёте прогноза, в том числе для новой карточки. При неизменной базе переиспользуются готовые параметры; векторы пересчитываются только для изменённых описаний. Уже сохранённые карточки и разборы сохраняют свои значения до обновления; полная команда применяет актуальные веса ко всей коллекции.

`predict_rating.js` объединяет одиночный, массовый и рекомендательный расчёт; `update_ratings.js` сохраняет результаты команды **«Кино - Обновить оценки»**. Новая карточка рассчитывается автоматически после заполнения ролей и франшизы. ChatGPT, Codex, отдельный сервер, Node.js, Python и платный API для обычного расчёта не нужны.

Текущие данные находятся в `Кино/_system/Прогноз/`: `embeddings.json` — кеш сюжетных векторов, `training.json` — параметры и результаты проверки, `queue.json` — незавершённые задачи, `reports/` — текущие разборы. При успешном обновлении карточки прежний разбор заменяется новым; архивы и резервные копии прогнозов не накапливаются. Поле `Прогноз оценки` остаётся итогом для каталога и рекомендаций, `Прогноз по данным` и `Прогноз по сюжету` содержат две составляющие. Поле `Оценка` прогнозатор не меняет.

Для телефона нужны актуальные служебные папки кинотеки и библиотеки и папка `Прогноз/`. CSS загружается из служебных папок без сниппетов; карточки и страницы подключают его самостоятельно, даже без запуска локального плагина. После синхронизации обновления полностью перезапусти Obsidian и открой главную кинотеки или библиотеки. Локальный плагин `.obsidian/plugins/book-preview-defaults/` обеспечивает также загрузку стилей сразу при запуске приложения. Локальная модель с библиотеками занимает около **354 МБ**; загружать её из Интернета во время расчёта запрещено. Браузерное вычисление проверено на ПК; **настоящий Android физически ещё не проверен**. Если модель недоступна или получить достаточный сюжет не удалось, сохраняется предварительный прогноз по данным и задача остаётся в очереди. Подробности — [[Кино/_system/Прогноз/README|инструкция по прогнозам]].

## Просмотры и сезоны

- История просмотров внутри карточки — обычный Markdown с номером, датой, оценкой и полным комментарием, как разделы сезонов. Добавление, редактирование и «Пересобрать карточку» используют общий формат и обновляют его из отдельных записей. История читается без Dataview; оформление шапки и рекомендации по-прежнему используют плагин.
- `Кино/Просмотры/_index.md` и `Кино/Сезоны/_index.md` собирают записи через нативные Bases. Оформлены в общем стиле через сворачиваемые блоки Obsidian и `kino-design.css`, без Dataview. Представление «По дате» показывает новые записи сверху; колонка «Запись» открывает исходную заметку. Ссылки ведут к прежним представлениям и командам добавления/редактирования. Индексы исключены из выбора записи для редактирования.
- `add_viewing.js` создаёт запись в `Кино/Просмотры/` и перестраивает историю в карточке.
- `edit_viewing.js` изменяет существующую запись просмотра.
- `add_season.js` создаёт сезон в `Кино/Сезоны/` и обновляет сериал.
- `edit_season.js` изменяет сезон.
- `rebuild_card.js` пересобирает отображаемые блоки по служебным файлам.

Во всех этих операциях общий интерфейс сохраняет доступ к ролям и кнопку `🔎 Найти похожие` в верхнем ряду карточки.

## Франшизы

`Франшиза` -> `edit_franchise.js`. Карточки франшиз находятся в `Кино/Франшизы/`. Общий модуль `franchise_order.js` нумерует связанные произведения из кинотеки по дате релиза от раннего к позднему. Номера сохраняются в `Часть`; вручную вводить их при добавлении не требуется. При добавлении более раннего произведения, переносе или удалении связи номера остальных участников обновляются автоматически. При одинаковой дате используется стабильный порядок по названию.

Страницы франшиз используют общую шапку кинотеки, навигацию, золотые заголовки и оформленную таблицу. Они занимают всю ширину панели; на телефоне таблица прокручивается внутри своего блока. Таблица всегда следует дате релиза и использует ту же нумерацию, что карточки фильмов. Личные впечатления и источники сохраняются. В карточке фильма ссылка на франшизу оформлена рамкой с текущим номером, например «Друзья Оушена (1)». Команда «Франшиза» и добавление фильма подключают оформление автоматически к новым и существующим страницам.

## Книги и связанные произведения

В карточках книг, фильмов и сериалов связанные произведения показаны компактными строками. Пустой раздел скрыт. Учитываются прямые и обратные ссылки: `adaptations` у книги ↔ `Первоисточники` или прежнее `adapted_from` у кино; `related` ↔ `related` для других связей между произведениями.

Кнопка **Связать с книгой** в кино и **Связать с кино** в книге запускают прежнюю команду **Книги - Связать с кино**. Она сразу сохраняет обе стороны выбранной связи и обновляет открытые карточки. Повторное добавление не создаёт дублей; при ошибке второй записи отменяется только добавленная этой операцией ссылка. Оценки, история, отзывы и остальные свойства сохраняются.

Связи проверяются командой **Книги - Проверить библиотеку** и структурным отчётом `Книги/_system/Проверка связей с кино.md`. Однозначные обратные ссылки поддерживает **Книги - Исправить безопасное**. Названия сами по себе не создают связь: экранизации и другие связанные произведения сохраняют отдельные свойства.

## Проверка и исправление

Рекомендуемый порядок после крупных изменений:

1. Запустить `Кино - Проверить кинотеку`.
2. Посмотреть `Кино/_system/Проверка кинотеки.md`.
3. При однозначных форматных ошибках запустить `Кино - Исправить безопасное`.
4. Повторить проверку.

Аудит проверяет YAML, ID, связи, роли, имена людей, дубли, просмотры, сезоны, франшизы, наличие раскрывающегося блока ролей и единственной кнопки рекомендаций.

## Структура

- `Кино/Media/` - основные фильмы и сериалы.
- `Кино/Просмотры/` - отдельные просмотры.
- `Кино/Сезоны/` - сезоны сериалов.
- `Кино/Франшизы/` - франшизы.
- `Кино/_system/Роли/` - companion-файлы актёров/ролей.
- `Кино/_system/Прогноз/` - модель, кеш векторов, параметры, очередь, текущие разборы прогнозов и состояние рекомендаций.
- `Кино/_system/` - скрипты и служебные страницы.
- `Кино/_system/_Кино.base` - основная база представлений.
- `Кино/_system/Аналитика прогнозов.md` - аналитика качества прогнозов.

## Что не надо делать вручную

- Не копировать роли обратно в тело карточки - они живут в `_system/Роли/`.
- Не редактировать `рекомендации_state.json` вручную.
- Не запускать BAT каталога после каждого добавленного фильма.
- Не удалять маркеры генерируемых блоков: по ним скрипты сохраняют личный текст при перестройке карточки.

## Сохранность данных

Добавление, редактирование и пересборка карточек сохраняют личные заметки и неизвестные свойства. Прогнозатор записывает только собственные поля и текущий разбор; личную оценку и историю просмотров он не изменяет. Перед записью проверяется, что карточка не изменилась во время вычисления. При таком конфликте обновление нужно повторить из Obsidian.
