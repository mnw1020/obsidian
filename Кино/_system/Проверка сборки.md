## Поведенческая проверка

Проверены не только тексты скриптов, но и их выполнение в тестовом Obsidian-подобном окружении. Скриптам выдаются файлы кинотеки, активная карточка, QuickAdd-ввод и ответы `requestUrl`, после чего проверяется фактический результат на диске.

Успешно пройдены сценарии:

1. `Examples_Attachments_movies.js` - добавление по КП ID: создаётся карточка, файл ролей, раскрывающийся блок, кнопка рекомендаций и прогноз.
2. `Examples_Attachments_movies.js` - поиск по названию: первым вызывается КП API, затем при необходимости резервные источники.
3. `update_kino_roles.js` - КП API возвращает актёров, роли и режиссёра; файл ролей реально обновляется.
4. `рекомендации.md` - КП API `/similars` формирует TOP-20; для результатов получаются прямые КП-ссылки и описания. Проверены также fallback-ветки похожих и деталей.
5. Кнопка `🔎 Найти похожие` - реально обновляет `рекомендации_state.json` и открывает `_system/рекомендации.md`.
6. `add_viewing.js` / `edit_viewing.js` - создают и редактируют записи просмотров, обновляют сводные поля карточки и не теряют постоянные блоки.
7. `add_season.js` / `edit_season.js` - создают и редактируют сезоны, пересобирают сериал и сохраняют постоянные блоки.
8. `rebuild_card.js` - пересборка не удаляет роли, кнопку или постер.
9. `edit_franchise.js` - создаёт/назначает франшизу и номер части.
10. `predict_rating.js` - записывает прогноз, уверенность, метод и локальный слой.
11. `predict_all_ratings.js` - массово проходит всю кинотеку без ошибок.
12. `audit_kino.js` / `safe_fix_kino.js` - аудит строит отчёт, безопасное исправление не меняет неоднозначные данные.
13. `compact_kino_people.js` / `migrate_kino_roles_files.js` - фактически переписывают нужные поля/блоки и после этого аудит продолжает работать.
14. `migrate_kino_entities.js`, `open_kino_actor.js`, `open_kino_director.js`, `open_kino_genre.js` - создают/обновляют динамические страницы и QuickAdd-команды; выбранная сущность реально записывается в YAML.

## Ограничение проверки внешней сети

В рабочем контейнере нет DNS-доступа наружу, поэтому живой запрос с личным API-ключом к Kinopoisk Unofficial из этой среды выполнить нельзя. Сетевые сценарии прогнаны через совместимый mock `requestUrl`: проверены URL, заголовок `X-API-KEY`, обработка HTTP-ответов, заполнение карточек и fallback-логика. Живую доступность сервиса подтверждает уже запуск в Obsidian на компьютере пользователя.

## Предупреждения о данных

Есть существующая неполная карточка `Без названия.md`:

- одновременно стоят теги `movies` и `serial`;
- нет `Кинопоиск ID`;
- нет осмысленного названия/метаданных.

Она не исправлялась автоматически, чтобы не потерять пользовательские данные. Companion-файл ролей для неё существует, служебная структура не разорвана.

Отдельные предупреждения аудита по ролям или повторным внешним ID относятся к исходным данным карточек, а не к падению скриптов.

## Повторная проверка

После финальных исправлений сборка повторно проходит статическую проверку. Финальный ZIP дополнительно проверяется на целостность и повторно распаковывается для контрольной проверки.
