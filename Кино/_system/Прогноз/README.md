# Три прогноза: данные, сюжет и итог

В карточке фильма или сериала блок «Прогноз» показывает крупный итог слева и две составляющие справа, на той же высоте:

| Оценка | Как рассчитывается |
| --- | --- |
| По данным | Публичные рейтинги, свойства карточек, калибровка и поправка до 155 соседей с наибольшим общим весом |
| По сюжету | Только описания и личные оценки соседей, найденных локальной EmbeddingGemma 300M q8 |
| Итог | Взвешенная смесь двух неокруглённых прогнозов |

Нажатие на блок открывает окно **«Как получен прогноз»** с вкладками **«Итог»**, **«Данные»** и **«Сюжет»**. Окно читает сохранённый разбор, соответствующий показанным оценкам; повторное вычисление при открытии окна не запускается. В разборе доступны дата, версии, исходные значения, точные формулы, коэффициенты, соседи, их личные оценки, сходство, веса и вклады.

## Расчёт и точность

Начиная с версии 6 влияние каждой личной оценки зависит от расстояния между **датами просмотров** — полями `Просмотрено` оцениваемой карточки и её соседа. Год релиза в этот множитель не входит. Вес плавно уменьшается в обе стороны от даты оцениваемого произведения:

```text
Расстояние = |дата просмотра соседа − дата просмотра оцениваемой карточки| в днях
Вес времени = exp(−ln(2) × расстояние / 730)
```

В тот же день вес равен 1, через 730 дней — 0,5, через 1460 дней — 0,25. Для карточки без даты просмотра используется текущая местная дата, зафиксированная в расчёте. Если дата отсутствует у соседа, его временной множитель равен 1; это отмечается в разборе. Даты не подменяются датами релиза.

Ветка по данным сравнивает карточку со всей оценённой обучающей базой, а соседскую поправку строит максимум по 155 произведениям с наибольшим общим весом. Сосед получает вес `похожесть³ × вес времени`; временной множитель учитывается до отбора соседей. Средняя личная оценка, калибровка публичных рейтингов и поправки по категориям используют всю обучающую базу с теми же временными весами относительно оцениваемой карточки. Описание сюжета в признаки этой ветки не входит. Год релиза по-прежнему участвует в сходстве метаданных, отдельно от веса по датам просмотров.

Сюжетная ветка сравнивает косинусное сходство смысловых векторов описаний. Жанры, актёры и публичные рейтинги в неё не добавляются. Вес соседа равен `exp((сходство − максимальное сходство) / температура) × вес времени`. По этому общему весу выбирается заданное число соседей; максимальное сходство берётся среди всех допустимых кандидатов до отбора. База равна взвешенной средней личной оценке: `Σ(вес времени × оценка) / Σвременных весов`. Прогноз равен этой базе плюс `Σ(вес соседа × (оценка соседа − база)) / (Σвесов соседей + сглаживание)`; результат ограничивается диапазоном от 1 до 10.

Параметры сюжета подбираются независимо по его собственной ошибке: число соседей — 10/20/35/55/100/155, температура — 0,03/0,07/0,15, сглаживание — 0/3/10. В подборе действует та же формула временных весов. Подбор проверяется вложенной перекрёстной проверкой: пять внешних и четыре внутренних разбиения, с группировкой дубликатов по IMDb/КП ID. Для оценённого произведения параметры подбираются без его внешней группы; для нового используются параметры по всей оценённой базе. Само произведение и его дубликаты исключаются из собственного обучения и подбора параметров.

Итог всегда объединяет оба готовых прогноза. Надёжность источников определяется по средней абсолютной ошибке (MAE) на одних и тех же внутренних проверочных карточках, чьи оценки скрыты от обучения:

```text
Вес данных = MAE сюжета / (MAE данных + MAE сюжета)
Вес данных ограничивается диапазоном 0,25–0,75
Вес сюжета = 1 − вес данных
Итог = вес данных × прогноз по данным + вес сюжета × прогноз по сюжету
```

Используются значения до округления; только результат округляется до десятых. Меньшая ошибка даёт больший вес. Ограничение 25–75% сохраняет вклад обоих источников. Если проверено меньше 30 пар карточек или 30 разных произведений, либо сумма ошибок нулевая или недоступна, используются равные веса 50/50. При отсутствующем сюжете итог временно равен прогнозу по данным и отмечается как предварительный.

Актуальные ошибки независимой внешней проверки (MAE и RMSE) и веса источников сохраняются в `training.json` и показаны в разборах карточек. Показатели прежней версии без временных весов к версии 6 не применяются. У уже оценённых карточек веса могут отличаться: они получены без соответствующей внешней группы. Итог сохраняет вклад обоих источников; его преимущество над отдельной веткой определяется проверкой, а не предполагается заранее. Даже при разных составляющих округлённый итог иногда совпадает с одной из них.

## Обновление внутри Obsidian

Новые карточки рассчитываются автоматически после заполнения ролей и франшизы. Для обновления существующей карточки вызови **QuickAdd: Кино - Обновить оценки** из неё. Для всей кинотеки открой **«Проверка кинотеки»** и нажми **«Обновить оценки»**: команда пересчитает обе составляющие и итог, заново подберёт параметры и запишет текущие разборы. Отображаются прогресс и кнопка остановки.

При следующем расчёте после изменения личных оценок или дат просмотров прогнозатор автоматически повторяет проверку точности и обновляет веса. Он сравнивает отпечаток актуальной оценённой базы с сохранённым: учитываются оценки, даты просмотров, признаки, описания, доступные векторы, правило временного веса и версии модели и алгоритма. При неизменной базе используются готовые параметры. Изменение оценки или даты просмотра не требует заново вычислять векторы сюжетов. Проверка выполняется внутри Obsidian с прогрессом и возможностью отмены; при отмене прежние параметры сохраняются.

Уже сохранённые прогнозы и разборы остаются снимками своего расчёта до обновления соответствующей карточки. Для применения новых весов ко всей коллекции используй полное обновление. Открытие окна разбора ничего не пересчитывает.

При прерывании незавершённые карточки остаются в очереди; работа может продолжиться при следующем открытии кинотеки или повторном запуске команды. Если сюжет получить не удалось или модель недоступна, показываются причина, готовый прогноз по данным и предварительный итог. Сюжетная оценка не выдумывается. Личная оценка в поле `Оценка`, заметки и история просмотров сохраняются.

## Что хранится

Все пути ниже относятся к `Кино/_system/Прогноз/`:

| Путь | Содержимое |
| --- | --- |
| `runtime/` | Закреплённая модель EmbeddingGemma q8, токенизатор, JavaScript, WASM и лицензии |
| `embeddings.json` | Векторы описаний, их отпечатки и версия модели |
| `training.json` | Подобранные параметры, веса и результаты независимой проверки |
| `queue.json` | Незавершённые задачи |
| `reports/` | Текущий разбор каждой карточки |

При успешном обновлении карточки ссылка `Расчёт прогноза` указывает на новый разбор, а прежний неиспользуемый разбор удаляется. В версии 6 разбор также хранит опорную дату, период уменьшения веса, даты просмотров соседей, расстояния в днях и временные множители. Они показаны под названием каждого соседа в прежней колонке, без дополнительных широких колонок. Старые разборы остаются читаемыми и показывают формулы своей версии. История снимков и резервные копии прогнозов не накапливаются.

В свойствах карточки `Прогноз оценки` хранит итог для каталога и рекомендаций, `Прогноз по данным` — вариант с 155 соседями, `Прогноз по сюжету` — EmbeddingGemma. Также сохраняются ссылка на текущий разбор, статус, дата и версия расчёта. Отдельные файлы состояния и кеша рекомендаций в этой папке используются страницей **«Рекомендации»** и не относятся к архивам прогнозов.

## Локальная модель и телефон

Используется **onnx-community/embeddinggemma-300m-ONNX**, ревизия `5090578d9565bb06545b4552f76e6bc2c93e4a66`, q8, 768 измерений. Текст получает префикс `task: sentence similarity | query: `; используется нативный `sentence_embedding` с нормировкой. Ограничение — **512 токенов**, обрезание отражается в разборе.

Модель запускается в отдельном Web Worker внутри Obsidian через WebAssembly с одним потоком. Вектор кешируется по описанию и версии модели; для нового фильма вычисляется только недостающий вектор. После первоначальной установки загрузчику запрещены сетевые обращения. ChatGPT, Codex, отдельный сервер, Node.js, Python и платный API для обычной работы прогнозов не нужны. Интернет может понадобиться для получения сведений о новом фильме из Кинопоиска.

Для телефона нужно синхронизировать служебные папки кинотеки и библиотеки и папку `Прогноз/`. Карточки и страницы сами подключают общий CSS из этих папок без сниппетов, независимо от запуска локального плагина. После обновления полностью перезапусти Obsidian и открой любую главную. Плагин `.obsidian/plugins/book-preview-defaults/` дополнительно обеспечивает загрузку стилей при старте приложения, в том числе для прямого открытия нативной базы. Модель с библиотеками и лицензиями занимает **353 972 419 байт, около 354 МБ, 17 файлов** без самого манифеста. Дополнительно занимают место кеш векторов и текущие разборы.

Внутри настольного **Obsidian 1.14.4** проверено свежее вычисление двух векторов по 768 чисел с корректной нормировкой. Загрузчик изолирует Node.js-глобальную переменную `process` только внутри своего Worker, чтобы библиотеки выбирали браузерный WebAssembly. Дополнительно проверены браузерное вычисление, обрезание длинного текста, отмена, повторный запуск, выгрузка и отсутствие модели; внешних запросов модели не было. **На настоящем Android запуск физически ещё не проверен.** Поддержка WebAssembly сама по себе такую проверку не заменяет. Модель требует заметного объёма оперативной памяти; при доступной обработке ошибки сохраняется предварительный прогноз по данным, а задача остаётся в очереди.
